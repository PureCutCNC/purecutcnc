Files: `src/components/cam/GenerationSettingsMenu.tsx`, `src/components/ToolpathVisibilityPanel.tsx`, `src/components/ToolpathRendererControl.tsx`, `src/components/canvas/useSketchToolpathRenderer.ts`, `src/components/canvas/SketchCanvas.tsx` (one small publish hook only), a new `src/store/toolpathRendererStore.ts`, `src/App.tsx`, `src/app/toolpathGeneration/{useExecutorPreference.ts,executorPreference.ts,executorPreference.test.ts,INDEX.md}`, the gear-menu and toolpath-legend rules in `src/styles/layout.css` (and wherever `.viewport-toolpath-renderer*` / `.viewport-toolpath-vis__gpu` live), `appShell.*` keys in the five `appShell.ts` locale modules. **Do not edit `CAMPanel.tsx`.** It only spreads `generationSettings` into `<GenerationSettingsMenu>`, so changing the props type in `GenerationSettingsMenu.tsx` and the object built in `App.tsx` (~line 476) is enough.

Today: the gear in the operations toolbar (`GenerationSettingsMenu`) shows the status, Stop / Resume / Retry, and a "Compute" section choosing Main thread or Background thread (`executor`, `onExecutorChange`, `workerAvailable`, stored in localStorage key `purecut.generation.executor` by `useExecutorPreference`). The sketch's toolpath legend (`ToolpathVisibilityPanel`) starts with a "GPU" button (`ToolpathRendererControl`) that toggles GPU / Canvas. When the GPU can't start it shows `ToolpathRendererFallback` ("GPU unavailable; using Canvas." + Retry GPU), which wraps the legend onto two rows. Renderer state lives in `useSketchToolpathRenderer` inside `SketchCanvas` (`toolpathRenderer.control`: `choice`, `status`, `onChange`, `onRetry`, `suggestion`).

## Build
1. **(7) No compute choice.** Remove the Compute section and the `executor`, `onExecutorChange` and `workerAvailable` props from the menu and from `App.tsx`. Generation always uses the worker when the runtime has one; the existing automatic fallback to the main thread (`status.executorFallback`, flagged gear) stays exactly as it is. In `executorPreference.ts`, add a pure `effectiveExecutorKind(stored, workerAvailable, development)`. In production it ignores the stored value: `worker` if available, else `inline`. In development (`development === true`) it still honours a stored `inline`, so the e2e parity spec can force the main thread. `useExecutorPreference` passes `import.meta.env.DEV`. Keep the storage key and codec for that dev use, and say so in a comment and in `INDEX.md`. A user who stored `inline` in an older build gets the worker in production.
2. **(13) GPU / Canvas switch moves into the gear.** New `src/store/toolpathRendererStore.ts` (zustand, like the other stores) holding `{ choice, status } | null` plus stable `setChoice` / `retry` callbacks. `useSketchToolpathRenderer` (or `SketchCanvas`) publishes into it in an effect keyed on `choice` and `status` only. Pass the callbacks through a ref, so the published object does not change every render and nothing re-publishes in a loop. It clears the store on unmount. The gear menu gets a "Display" section under the status, shown only when the store has a value: the existing label `appShell.toolpath.renderer` and two buttons `GPU` / `Canvas` (`aria-pressed`), plus `rendererLoading` text while loading. Remove the GPU button from the legend; the legend now starts at Cuts. The "Try GPU" suggestion (`ToolpathGpuSuggestion`) stays in the legend as it is.
3. **(11) GPU fallback on the gear.** When the renderer status is `'fallback'`: the gear gets the same `cam-generation-gear--flagged` state as a worker fallback, its `title` and `aria-label` append `appShell.toolpath.rendererFallback`, and the Display section shows that sentence with a `Retry GPU` button (`rendererRetry`) calling `retry`. Remove `ToolpathRendererFallback` from the legend. Delete the now-unused components in `ToolpathRendererControl.tsx`, or the file if empty. Note in RISKS that the fallback is now only visible where the gear is (issue #786 had asked for it to stay visible when the legend is collapsed; Frank approved moving it).
4. **(12) Feature colours legend starts closed.** In `App.tsx`, the `DEPTH_LEGEND_COLLAPSED_STORAGE_KEY` default goes from `false` to `true`. A stored choice is kept.
5. Remove the locale keys left unused (the Compute section's `appShell.generation.backendInline`, `backendWorker` and their `…Detail` keys, and whatever else only the removed UI used) from all five packs. Grep each one first. Add a key only if no existing one fits (e.g. `appShell.generation.display` "Display").
6. Tests: `effectiveExecutorKind` (prod + stored inline → worker; prod + no worker → inline; dev + stored inline → inline) in `executorPreference.test.ts`. A pure `gearFlagged({ paused, failed, workerFallback, rendererFallback })` with a test.
