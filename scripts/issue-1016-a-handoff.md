## Approved behavior

The input parameters are not saved; only existing line/folder/operation/tool shapes are persisted. No format/version or postprocessor/generator change.
- Thread input: start along bar, length, physical pitch in project units, starts (default 1), depth (UI default .61*pitch). Right-hand only. With n starts, lead = n*pitch; each line advances that lead along the bar per full turn, starts evenly C/n apart across. Inch UI will convert threads-per-inch to physical pitch before calling the helper. V-bit required; UI note says approximate decorative/wood/plastic thread, not a substitute for proper thread tooling. No automatic relief/run-out.
- Flutes input: start, length, count, twist in turns over the requested length (0 straight), depth, selected tool. Lines are evenly spaced C/count and each spans twist*C across while covering requested length.
- Depth is from bar surface, strictly above centreline; refuse nonfinite/nonpositive pitch,length,depth, invalid/noninteger counts and a depth reaching the radius. Respect current Around project/machine/axis refusals. Creation away from available Around must leave state untouched.
- Start is distance from the stock's minimum along coordinate; geometry stays between start and start+length. Preserve approved allowance for user-specified lines extending past a bar end; no silent clipping. Across coordinates use the centered Around frame's zero line (aroundFrame.zero), not the sheet's lower edge as zero. Do not reduce multi-turn coordinates modulo circumference.
- Use frozen rotary sign/frame convention and independently verify the right-hand slope on both axes; don't change aroundFrame/rotaryFrame.
