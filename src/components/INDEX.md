# INDEX — src/components/

React UI. Components are organized by feature area. Plain CSS for styling — no UI libraries.

## Top-level files
- `AppErrorBoundary.tsx` — top-level React error boundary
- `ErrorScreen.tsx` — fatal-error fallback UI
- `Icon.tsx` — `<Icon id="..." />` renders an SVG sprite reference (`icons.svg#id`)
- `IconGallery.tsx` — dev/debug grid of all available icons
- `Select.tsx` — shared styled `<select>` wrapper; an option may carry a `group` heading (consecutive options sharing one render a single non-interactive label), which the project machine picker uses for "Other machines" (issue #1028)
- `ToolpathVisibilityPanel.tsx` — toggles for showing/hiding toolpath layers
- `ToolpathLevelRail.tsx` / `toolpathLevels.ts` / `useToolpathLevelSelection.ts` — transient, display-only level selection for planar multi-level operations; shared by the 2D and 3D previews while surface and waterline paths fail closed to the complete view
- `ToolpathGpuSuggestion.tsx` — non-blocking GPU tip for a stored Canvas choice, outside the toggle row; `canvas/toolpathGpuSuggestion.ts` detects repeated slow navigation draws, and `canvas/useToolpathGpuSuggestion.ts` owns browser-local dismissal and result-scoped suggestion state.
- `plasmaKerfPreview.ts` — the display-only plasma kerf model (issue #961): the torch's kerf width in project units and the identity-cached split of a toolpath's moves into contour, lead and pierce geometry. Nothing here generates, stores or exports, and it is covered by `plasmaKerfPreview.test.ts`.
- `toolpathSetupMuting.ts` — which operations' toolpaths the 2D and 3D previews draw muted: those cut in a setup the workspace is not on (issue #947), by the same membership rule as the simulation and export; nothing for a single-setup project
- `toolpathVisibility.ts` — `ToolpathVisibility` type, default visibility constants, and the cached feed-colour legend steps (issue #535) (kept out of the panel component for fast refresh)
- `UnsupportedMobileScreen.tsx` — phone-sized-device blocker screen shown instead of the app (extracted from `main.tsx`)
- `errorFormat.ts` — shared error formatting
- `useIconIds.ts` — hook listing available icon IDs

## Subfolders (by area)
- `common/` — shared cross-panel UI primitives. `DisclosureSection` is the reusable collapsible "Advanced" section (progressive disclosure); its open/collapsed state persists via the pure helpers in `common/disclosureState.ts`. `UncutWorkBadge` / `UncutWorkNote` draw the "kept but cannot be cut" marker and note (issue #1112 K), whose text comes from `cam/uncutWork.ts`. `NoEffectBadge` draws the "later features cover it" marker (issue #1112 N), fed by `app/featureEffect/`. `formDraft.ts` answers "does this form have something to save?" for a dialog with an explicit Save/Apply (issue #1112 F4): `formHasChanges` compares the draft and the saved values **by value**, so a draft rebuilt on every keystroke is not mistaken for an edit, and each caller normalises first the way its own save path does. `renameTarget` applies the same rule to an inline rename's trimmed name, returning the name Save would write or `null` when an unchanged, reverted, or blank draft writes nothing — which is exactly when the rename's Save is disabled.
- `canvas/PlasmaStartPointPicker.tsx` / `canvas/plasmaStartPoint.ts` — plasma contour click/tap capture with compact draggable shared edit controls, attached per-contour markers and targeted closed-contour projection, covered by `canvas/plasmaStartPoint.test.ts`; transient pick intent lives in `cam/plasmaStartPointPick.ts`.
- `canvas/plasmaKerfBand.ts` — the 2D sketch's plasma kerf preview (issue #961): a translucent one-kerf band under the centre line, contour segments under `cuts` and lead segments under `leadIns`, plus fixed-size pierce markers under `plunges`; pure view code, covered by `canvas/plasmaKerfBand.test.ts`.
- `canvas/` — 2D sketch canvas: drawing, snapping, panning/zoom, pointer handling, creation workflow panels, and overlap disambiguation through `useOverlapFeaturePicker` / `OverlapFeaturePicker`. `CanvasWorkflowAction` and `canvasShortcuts.ts` keep every canvas-panel action’s accessible label, visual shortcut hint, and keyboard binding aligned; `EditSketchPanel` owns the active sketch-edit session’s controls and confirmation handoff. `FeatureDistributionPanel` / `useFeatureDistributionWorkflow` provide the one-shot grid/radial/path copy workflow (issue #205), with canvas preview driven by `sketch/featureDistribution.ts`. `TextLayoutPanel` / `useTextLayoutWorkflow` lay an **already placed** text run on a circle or along a guide (issue #671) — a post-create edit reached from the same arrange group as distribution, not part of the text tool; `canvas/textLayoutPreview.ts` draws what Apply would produce, and preview and commit share `sketch/textPlacement.ts` so they cannot drift apart. `previewPrimitives.ts` keeps Line/Construction geometry stroke-only and draws a gear being created with its bore, since `buildGearProfile` never includes one (issue #1112 R2 item 12); `previewPrimitives.test.ts` covers both the rendering-role policy and that pending-gear bore. `stlTopViewRenderer.ts` maps imported-model top-view images through their full instance transform, covered by `stlTopViewRenderer.test.ts`. Dimension annotations + tape measure render via `canvas/dimensionRendering.ts` (pure geometry in `sketch/dimensions.ts`); `canvas/operationSnapshot.ts` renders static operation booklet images; `drawOperationSnapshot` is the context-agnostic drawing half, and since issue #924 it draws the toolpath through the same display merge as the live canvas rather than stroking every emitted move (`operationSnapshot.test.ts`). `canvas/toolpathDisplay.ts` owns the display-only scaled-world toolpath cache: it coalesces same-style strokes up to three canvas pixels of accumulated travel and indexes lines, collisions, source markers, and arrows so panning queries only the canvas viewport without changing emitted motion. `canvas/navigationActivity.ts` and `canvas/useNavigationViewState.ts` defer direction-arrow calculation/drawing while navigating, restoring detail after pointer release or 150 ms wheel idle without changing visibility settings. `canvas/toolpathDisplayFixture.test.ts` measures geometric error against the original rectangle and 882,899-move raster workloads. `canvas/toolpathArrows.ts` owns the 2D direction-arrow placement pass, cached per `(toolpath, scale, visibility)` and stored in scaled-world space so panning only shifts it by the view offset and still hits — that pass was 93.7 ms per animation frame on #664's 249,663-move fixture against 26.7 ms to draw the 9,899 arrows it selects. `toolpathArrows.test.ts` pins the rules and then pins the port itself against the pre-#664 algorithm transcribed as an oracle, on the real fixture. `canvas/CanvasCreationPanel.tsx` is the creation side-panel markup extracted from `SketchCanvas` (pure move, keeping that file under its max-lines cap), and `canvas/CannedShapeEditPanel.tsx` reopens a canned shape's stored parameters in that same page-level side panel from a `canned-edit` pending session (issue #1112 DE2); since #1112 rt2-b the four rotary kinds join them there instead of opening a modal: `canvas/RotarySolidPanel.tsx` (Turn/Polygon, creatable from Top, Bottom or Around on either bar shape) and `canvas/RotaryPatternPanel.tsx` (Thread/Flutes) share the panel chrome through `canvas/useRotaryPanelChrome.ts`, close on a bar/unit/document/face change through `canvas/rotaryPanelContext.ts`, and carry the Turn's profile picker with its drawing hint, hidden Refresh for None and inline half-profile picture (items 16/17); since #1112 F1 every valid field value previews live through `useCannedShapePreview.ts` (root of this folder), which writes the draft inside one history transaction, commits it as one undo step on Apply and, on Cancel/Escape, puts back only the data the preview wrote — an unrelated change made while the editor was open (a stock resize, a unit switch) survives; `canvas/cannedShapeLivePreview.test.ts` drives every editor for every canned kind, one field at a time, including the direction and profile pickers and Save/Apply plus one undo for each kind.
- `viewport3d/` — Three.js 3D preview of the CSG-derived model, including toolpath overlay helpers, shared camera orbit controls (`orbitControls.ts`), view-preset data (`viewPresets.ts`, whose isometric view looks up from below while the workspace is on Bottom, #947), and the single-button view dropdown (`ViewPresetMenu.tsx`) used by both the 3D and simulation viewports. `toolpathOverlay.ts` owns the **shared** toolpath layer set — which move kinds each layer draws and, for rapids, which half of the Z split (`zFilter`) it claims — consumed by both this viewport and the 2D canvas so the two views cannot disagree about layer membership (issue #482). It also owns `toolpathLayerBuckets`, the identity-cached one-pass version of that split both renderers use on the render path — the per-layer filter it replaced was five full copies of the move array per animation frame (issue #664). It owns the wrapped Around display too (issue #395): `stockSpaceToolpath` maps a path whose points carry the rotary angle `a` onto the bar with `stockSpacePoint`, subdividing each turning move into pieces of at most 5° so the curve follows the bar, while an angle-free path is handed back as the very same object and moves array. `arrowBatch.ts` draws every direction arrow of one colour as two objects (a `LineSegments` of shafts plus an `InstancedMesh` of heads) instead of a `THREE.ArrowHelper` each; on #664's 249,663-move fixture that was 29,741 scene objects and 19,835 draw calls per frame, which the viewport's render loop re-submitted for the life of the session. Its geometry reproduces `ArrowHelper` exactly and `arrowBatch.test.ts` asserts that against a real `ArrowHelper` rather than against recorded numbers. `webglRenderer.ts`, `webglContextGuard.ts` and `WebglStatusOverlay.tsx` are the WebGL failure handling both 3D views share: renderer creation returns `null` instead of throwing when the browser denies a WebGL2 context, so a GPU-less browser still opens the 2D workspace rather than the error screen (issue #786); the guard forwards context loss and restore; the overlay explains either state with each view's own messages. Feature meshes follow the same in-place highlight rule as the fixtures (issues #261, #1112 F5): selecting or hovering a feature recolors the mesh it was built as — for a Turn or Polygon, the only mesh it has — so the scene-build effect stays geometry-keyed and a highlight never rebuilds the CSG model.
- `viewport3d/plasmaKerfObjects.ts` — the plasma kerf band and pierce markers for the 3D preview and the Simulation tab (issue #961): a `worldUnits` `LineSegments2` band one kerf wide at the top of the sheet plus a fixed-size `THREE.Points` marker ring, with its own disposal; covered by `viewport3d/plasmaKerfObjects.test.ts`.
- `simulation/` — heightfield simulation viewport and playback controls, plus `SimulationSetupInfo.tsx` — the toolbar's fresh-stock info button (issue #1112 F3): the sentence as tooltip and accessible name, tap-opened on touch, rendered only when the project has another setup (its own test renders it in linkedom); `aroundView.ts` owns the Around bar pivot, frozen-sign turn and vertical tool pose, plus the frame-value key (`aroundFrameKey`/`sameAroundFrame`) the viewport's Around effects depend on instead of the rebuilt frame object's identity (issue #395 G3), all tested by `engine/simulation/aroundWrap.test.ts`; the key also carries the bar's shape and thickness so a square blank and a round bar of the same box, or a resized blank, never reuse a stale preview (issue #1016 C2-R2V). It also owns the bar readout (`barReadout`: the wrapped tool point in the real project origin plus the program's unreduced `a`), covered by `simulation/aroundView.test.ts`. An Around setup is drawn as the cut bar turning under the tool, with no separate flat view (issue #395 G3). `SimulationViewport` draws a round bar and a square blank through one heightfield path — `createHeightfieldTexture`/`createHeightfieldMaterial`, the instanced surface strips and `createInstancedBoundaryGroup` — and takes its bounds and framing from the grid's radial envelope (`grid.stockTopZ`, the corner radius on a square blank) about the true pivot, so taller corners are not clipped. Playback uploads only the controller's dirty rectangle with `uploadHeightfieldRegion` and falls back to `updateHeightfieldTexture`; static and playback results report removal against each cell's own starting height when the grid carries `initialTopZ`. The toolbar has no setup choice of its own (issue #1112 F3): the run follows the workspace face, and with more than one setup the fresh-stock sentence sits behind an info button at the end of the toolbar — its tooltip and accessible name, tap-opened on touch — instead of a full-width line under the controls.
- `cam/` — CAM panels (tools, operations, parameters); per-parameter reference icons via `OperationParameterReference`. `CAMPlanDialog` is the two-column CAM Plan review/apply surface; `CAMPlanOperationEditor` edits transient recommendations and reads `operationFields.ts` applicability so operation-specific controls stay aligned with the normal editor, while shared tabs have one separate setup row. `ToolLibraryDialog` renders the focused library-import modal, listing only the machine mode's own tool family (#960); the pure filtering/selection helpers live in `toolLibraryDialogModel.ts` with their own structural tests. `operationTargetLists.ts` computes the context menu's "Add/Remove to operation" candidates against the store's own `isOperationTargetValid` guard. `SurfaceSlopeFields.tsx` provides the optional min/max CL-surface slope controls for 3D finish operations. `operationFields.ts` declares the operation panel's field order and grouping as data — one ordered table of `{ id, group, paramRef, appliesTo }` that `CAMPanel` walks — so a control's position is a property of the field rather than of the JSX branch it was written into (#559). Which patterns the `pattern` dropdown offers is no longer the renderer's own list: both it and `operationFields.ts`'s applicability read `engine/toolpaths/pocketPatterns.ts`, the same table the generators dispatch on, so a kind can never be offered a pattern its generator does not implement (#609). `OperationAddMenu` partitions the Add menu on the same validity hint the rows already carried: kinds the selection can take render first, the rest collapse into one counted `DisclosureSection`, and an empty selection states its single precondition once instead of eleven times (#732); a row blocked by the stock shape stays in place, disabled with its reason, because the disclosure is about the selection. `operationAddEntries.ts` decides the menu's contents per face and stock: Around lists only wrapped work (no 3D surface strategies, no flat plasma cut) and leads with its rotary rows, and a square blank keeps the round-only rows listed in place, disabled with `cam.addMenu.squareBarUnavailable` — "Not available on a square bar yet", decision 17's wording, which replaced "Needs a round bar" because turning a square blank works and it is the sheet work that does not (issue #1112 K); its `validQuickOperationsForFeatureOnActiveFace` answers the feature context menu's Create-operation list for a feature authored on another face from the same table, so the two surfaces cannot offer different work (issue #1112 F2); `uncutWork.ts` supplies the user-facing reason for kept work the current stock or face cannot cut, shown on the feature row and the operation, with a feature row also claiming the centreline warning an operation got through it (issue #1112 K). - `cam/machineMode.ts` — the machine mode the CAM panel follows (issues #960, #1028): `machineMode` derives `router` or `plasma` from the **project type** — a plasma project is `plasma`, milling and rotary are `router` — and `operationOffer`, `operationCutOnMachine`, `uncutOperationCount`, `selectableToolTypes`, `libraryEntryOffered`, `showsFaceSwitch` and `showsMillingAuthoring` decide what that mode may add — restricting new offers while an existing operation or tool of the other family stays selectable as what it already is, and offering the plasma cut in a milling or rotary project as `needs-plasma-project`, a **project-type** reason rather than a machine one (issue #1034); `machineMode.test.ts` pins every rule in both modes. The CAM panel's Add menu and tool type list, the tool library and the workspace face switch all read it (#960); the Auto plan button and the Add-tab control are router-only.

## Conventions
- `cam/bookletExport.ts` — the operation booklet export as named stages (issue #924): preparing the toolpath, drawing the snapshot, building the PDF, choosing where to save. Each stage is announced before it starts and the two that hold the main thread wait for a paint first, so `CAMPanel`'s stage text and the booklet button's spinner describe the step actually running. `bookletExport.test.ts` pins the order.
- `cam/ScallopHeightField.tsx` — Constant scallop's single finish-quality input, with units, strict positive-height validation, and a display-only legacy stepover conversion that preserves saved output until edited.
- GPU sketch renderer, default since 0.6.0 (issue #1087; #683): `canvas/gpuToolpathRenderer.ts` retains full XY buffers and composites per-layer coverage masks; `gpuToolpathShaders.ts` owns screen-space shaders. `gpuToolpathAnnotations.ts` reuses Canvas arrow/debug rules in an operation-ordered texture. `useSketchToolpathRenderer.ts` owns lazy loading, cancellation, disposal and fallback/retry; `toolpathRendererPreference.ts` owns the application-local codec, the `gpu` default and the non-persisting DEV comparison override (covered by its test). `toolpathWebglSupport.ts` owns the one strict WebGL2 request (refusing software rasterisers), the DEV-only software-WebGL test switch and the suggestion probe, so the app never advertises a GPU that would fall back. `renderSketchToolpaths.ts` selects GPU or Canvas fallback without changing navigation ownership. Both backends draw a mirrored Bottom view from the same stock-space buffers (the GPU through a per-axis view map) and paint another setup's toolpaths muted, beneath the active setup's (#947). `toolpathStyles.ts` shares styles with Canvas/booklet output. A stored Canvas choice is kept and a runtime without hardware-accelerated WebGL2 (missing, or software-only on SwiftShader) falls back to Canvas visibly; booklet snapshots always use Canvas. See [`tools/gpu-toolpath-poc/`](../../tools/gpu-toolpath-poc/INDEX.md) for the comparison harness and device gates.
- Heavy compute (CSG, toolpath gen, sim) is debounced. See `Viewport3D` (150–300ms typical).
- Mutations go through `projectStore` actions only — never mutate Zustand state directly from components.
- For touch/tablet styling see `src/styles/tablet.css` and [`planning/TABLET_UX_DESIGN.md`](../../planning/TABLET_UX_DESIGN.md).

- `cam/PlasmaOperationFields.tsx` — plasma-only kerf side, swirl reversal, line/arc leads and optional contour-start XY; milling controls are excluded by the field policy.
- `cam/setupSections.ts`, `CamSetupSectionView.tsx` — CAM groups by saved or provisional active setup, program numbers, registration status and scoped export (#946). `SetupPropertiesDialog.tsx` / `SetupRegistrationEditor.tsx` edit flip axis, name, shared-origin display, references and notes; setup deletion lists operations before confirmation; since #1112 F4 Save is disabled while the form still holds the saved setup's values, and stays disabled when another path changed the setup underneath it. `SetupOperationControls.tsx` confirms validated Move and measures stock-Z reach; `OperationCuts.tsx` / `operationCuts.ts` show the operation's current targets only — each a compact row of the target's own icon (`cutRowIcon`: a canned shape by its kind, a plain feature by its `FeatureKind`, an imported mesh as an import), its name and a small remove ×, with hover highlight and folder grouping once the list is long (`layout.css` excludes that × from the field-rule that would stretch it over the row; rt3-a item 25), replacing the read-only Target line and both target checklists (issue #1112 I) — every target is a normal selectable row or an Around band now; since #1096 the panel also renders the standard "Use current selection" row for a rotary operation, so a selected closed Around region joins the target as a mask and a selected model narrows it (an update route requires a non-empty selection so a stray click cannot reset the target; the Cuts × is how a model is kept out); the same module's rotary operation and add-menu hints admit either bar shape, round or square, so a generated square-to-round model is a valid target with no spurious round-stock message while a block still reports it (#1016 C2-U1). `SetupDialogShell.tsx` supplies focus, Escape and scroll handling. An Around section in a project whose type is not rotary carries `CamSetupSectionView`'s note — the operations are kept but not cut (issue #1028).

- `cam/rotaryOperations.test.ts` — Rotary rough/finish authoring contract: Around model-only targets, defaults, support cache/units/file persistence and exact field policy (#1015 slice D).

- `canvas/aroundSelection.testSupport.ts` supplies the overlapping X/Y model fixtures for `useClickPlacement.test.ts`, `useCanvasContextMenu.test.ts`, and `aroundCanvasDraw.test.ts`; these exercise Around band picking and the live canvas hover/selection draw pass without flat model silhouettes (#1112 I2).

- `feature-tree/ChuckProperties.tsx` — chuck size presets, editable range, jaws and capacity warning (#1112 M); the old body is retained until a size is picked. A pick of the size or the jaws marks the chuck hand-set (`ChuckData.manual`), so a stock change no longer re-defaults it (#1112 R2 item 23); a size pick keeps the jaws it already had. `ChuckProperties.test.ts` checks rendered fields, warnings and both picks' patches.
- `canvas/aroundChuck.ts` — display-only chuck footprint and label, limited to one sheet height; snap/CAM bands are unchanged. `aroundChuck.test.ts` checks axial dimensions and clipping on both axes.
- `canvas/aroundDisplayWrap.ts` / `canvas/aroundFeatureDisplay.ts` — the display fold for the Around sheet (#1112 slice L, decision 8.13): an outline or toolpath past a seam is split and shifted into the sheet for drawing only (a 20-turn thread reads as stripes inside it), a path already inside stays the same object, and a hand-drawn sketch is never folded; `featureHitProfiles` folds the same way so a folded stripe is selectable. `canvas/aroundSheet.ts`'s `aroundSeamLabels` (+180° / −180° on the sheet edges) and `scenePrimitives.ts`'s band labels are covered alongside the fold by `aroundDisplayWrap.test.ts` and `aroundSheet.test.ts`.
