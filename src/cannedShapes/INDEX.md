# INDEX — src/cannedShapes/

Canned-shape model (issue #1112): a feature definition that stores a shape's
kind and parameters and generates its outlines on read, the way Text stores a
string and generates glyphs.

## Files

- `types.ts` — the extension point slices D–G code against: `CannedShapeGenerator` (`kind`, `labelKey`, `generate`, optional `generateMesh`/`capabilities`/`normalizeParams`/`convertParams`, `summary`), `CannedShapeOutline`, `CannedShapeSummary`, `CannedShapeMesh`, `CannedShapeCapabilities`, and `defineCannedShape` for type erasure at registration.
- `registry.ts` — generator and editor maps. Built-ins seed from `generators/`; tests register test-only shapes with `registerCannedShapeGenerator`. `registerCannedShapeEditor` is the hook later slices use to open their dialog from the Properties "Edit <shape>…" button.
- `index.ts` — the read path: `isCannedFeature`, `resolveCannedShapeShapes` (nesting depth → Add/Subtract, placement transform, mirror winding), `resolveCannedShapeProfiles`, `cannedShapeFrame`, `cannedShapeSummary`, `cannedShapeLabelKey`, `cannedShapeCapabilities`/`cannedShapeIsExpandable`, and `generateCannedShapeMesh`.
- `cache.ts` — generated-outline cache keyed on kind + canonical normalized parameters; a parameter change is a miss, registering a replacement generator clears that kind. Hit testing, hover and redraw share one generation.
- `model.ts` — the mesh half of the contract: builds a model kind's mesh into `Project.modelAssets` and points `definition.stl.meshAssetId` at it, so CSG, surface toolpaths, preview and export consume it like an imported model. A rebuild keeps the user's `stl.scale`/orientation, and `applyCannedShapeModelSpans` writes the regenerated height into every linked instance's Z span above its own bottom — the one value all consumers read. `rebuildCannedShapeModels` runs on load and unit conversion; `applyFeaturePatch` runs `rebuildCannedShapeModelDefinitions` and the span pass for a parameter edit.
- `generators/index.ts` — the built-in list. Slices D–G export a generator from their own module and append it here; nothing else in the model changes. A generator module imports `defineCannedShape` from `../types`, never from this package's index (that would cycle through the registry).
- `generators/ellipse.ts`, `slot.ts`, `ngon.ts`, `roundRect.ts`, `chamferRect.ts` — the five flat shapes (slice D). Each generates in definition-local coordinates through the same profile constructor the old one-shot command used, and each exports a `CannedShapeEditorRequest` (fields + the generator's own `normalizeParams`) that the canvas edit panel renders.
- `generators/gear.ts` — the gear (issue #1112 E): `buildGearProfile` at the definition origin plus an optional concentric bore circle, so the canned model's nesting rule gives an Add gear a Subtract bore and a Subtract gear an Add island. Parameters are the creation panel's set plus `outsideRadius`; lengths convert on a unit switch and the Properties summary reports teeth and module. `generators/gear.test.ts` compares the generated outline to the old one-shot `buildGearProfile` output across several parameter sets.
- `generators/thread.ts`, `generators/flutes.ts` — Around Thread and Flutes as canned features (issue #1112 F), one open `line` outline per start/flute. Parameters are the dialog's numbers plus a snapshot of the Around frame (`zero`, `circumference`, `radius`, `alongOrigin`, `alongDirection`), so the stored data regenerates every line without the project; start/length are measured from the chuck end (decision 4). Both call the same pure `engine/rotaryPatterns.ts` builder the pre-canned command used, so a Follow line operation on the feature cuts what the old folder's operation cut. Their tests equal the old builder's lines and cover signed twist, hand, unit conversion and refusal; `generators/rotaryPatternParams.ts` validates/converts the stored frame.
- `generators/kinds.ts` — the registry keys, shared by the generators and the creation actions so a stored `kind` cannot drift between the two.
- `generators/turn.ts`, `generators/polygon.ts` — Around Turn and Polygon as canned **models** (issue #1112 G): each generates a mesh through the same `buildRotaryCylinderMesh` / `buildRotaryPolygonPrism` the old Square to round and Polygon commands used, and declares `capabilities.expandable: false`. Parameters are the dialog's numbers plus a bar snapshot (`generators/rotarySolidParams.ts`) and, for Turn, the segment count, so save → load → regenerate is exact without the project. Their tests compare vertices and triangles to the old builders on both bar shapes and both axes, round-trip the stored JSON, check unit conversion and refusals.
- `generators/rotarySolidParams.ts` — the stored bar snapshot for Turn/Polygon (`axis`, `thickness`, absolute along ends, across centre), chuck-end start/length mapping, band/size validation and the frame → stock geometry adapter the builders take.
- `generators/editorRequest.ts` — what an "Edit <shape>…" panel needs from a generator (label, numeric fields, its own `normalizeParams`), with no React import.
- `generators/editorForm.ts` — the pure form half: stored parameters → field text, field text → a parameter set the generator's `normalizeParams` then validates.
- The canvas side panel lives in `src/components/canvas/CannedShapeEditPanel.tsx`: it registers an opener for the five kinds (and the gear) through `registerCannedShapeEditor`, and the Properties trigger arms the same `canned-edit` pending session creation uses. There is no modal and no second React root; Apply is one `updateFeature` write.
- `generators/shapes.test.ts` — generator-level properties: local outline equality, parameter refusal, unit conversion of length fields only, and determinism.
- `cannedShapes.test.ts` — model tests; runs the test-only generators from `src/test/cannedShapeFixture.ts` so the model is exercised independently of the shipped gear.
- `cannedShapeCache.test.ts` — three resolutions call a generator once, a parameter change misses, registration invalidates, and key order does not defeat the key.

## Rules

- Parameters are JSON-only (`CannedShapeParams`), so save → load → regenerate is exact.
- A kind with `generateMesh` is a model: its mesh is derived from the parameters, rebuilt on change/load/unit conversion, and non-expandable by default capability. A rebuild preserves `stl.scale` and the definition's orientation, and the regenerated mesh height reaches every consumer through the instance Z span (`z_top = z_bottom + meshHeight × scale`), including linked copies.
- A generator that stores lengths supplies `convertParams`; `convertProjectUnits` routes the definitions through it, so a unit switch converts the parameters with the frame.
- The stored `definition.profile` is a placement frame derived from the parameters, never the geometry; hit testing and rendering read the generated outlines instead.
- `capabilities.expandable` defaults to true. A model sets it false and Properties hides "Expand to features".
- Closed outlines nest by containment: depth 0 = the feature's operation, 1 = the opposite, 2 = the operation again. Open outlines keep the feature's operation.
