# INDEX — src/engine/simulation/

Material-removal simulation. Flat and round grids store a `topZ` heightfield
and render through a GPU heightfield mesh. A square bar stores every remaining
radial interval; `topZ` is only its outer envelope, and its boundary geometry
keeps disconnected material and real air gaps. Pure logic + Three.js mesh
builders — no React.

## Core
- `aroundWrap.ts` — compile-time Around shader chunks: shared wrap and radial-normal formulas, periodic neighbor lookup and render bounds; `aroundBounds` is centred on the true pivot and takes an optional radial maximum, so a square blank's corner envelope is `pivot ± side/√2` rather than a lifted `0..2·maxRadius` (the default keeps the round box byte-identical). The neighbour lookup is a preprocessor-free integer chunk (`AROUND_CELL_INDEX_GLSL`) so the scalar test support can run the GPU's own code; flat materials retain their original shaders
- `types.ts` — `SimulationGrid`, `DirtyRegion`, `SimulationBuildOptions`, `SimulationStats`; a square grid also carries the transient `squareMaterial` map of per-cell remaining canonical radial intervals (issue #1016 C2-R1F) — never persisted, `topZ` stays the derived outer envelope only
- `grid.ts` — grid spec resolution and `createSimulationGrid` allocation
- `tools.ts` — `cutterSurfaceZ`: the cutter's lower-surface profile used to lower cells
- `replay.ts` — periodic cutter copies at Around seams wrap outside the unchanged cut kernel; applies toolpath moves to the grid (`applyMoveToGrid`, `simulateOperationHeightfield`); a plasma torch cuts a flat one-kerf, full-depth slot along every torch-on move and a kerf-wide hole at each pierce; a `squareBar` grid dispatches to `squareMaterial.ts` and its stats count a cell whenever its remaining intervals lose material — including an interior band whose outer `topZ` never moved — against the grid's immutable square baseline; the flat/round cell loop is allocation-free with per-move cutter dispatch (see `replay.test.ts` for the reference-parity contract)
- `squareMaterial.ts` — the physical square material model and cut kernel (issue #1016 C2-R1F, contact window C2-R1G). Per cell it stores the remaining canonical radial intervals as a 1D CSG per ray, so an interior groove and a surviving outer lip are both representable and a later pass cannot resurrect removed material. A constant-angle move's removed set is exactly `[min floor, max reach]` over the ray's feasible parameter window, with the tip radius and the axial offset kept correlated (a sloping ball cut is no longer evaluated at a global lowest tip); the window is solved from the concavity of each body part's margin — a converged maximum plus bisected crossings, never a uniform pose scan — so a narrow window between scan nodes is still found (C2-R1G). The ball is the lower hemisphere **plus the cylindrical shank beyond its equator**. **Supported regime:** constant-angle cuts and plunges only. A move that changes the program angle below the blank's corner envelope sweeps a rotating body whose removed set is not certified at grid resolution and is refused with a `RangeError` before any material is touched; above the envelope such links stay safe zero-removal, and a constant explicit `a` is a constant-angle move even when `across` changes. `squareMaterialIntervals` is the frozen transient API the renderer consumes — read every pair, not just the outermost endpoint. Also `squareSurfaceRadius` and `validateSquareBarDescriptor`; `squareReplay.ts` is now a thin delegating entry point so the C2-R1 import surface is unchanged. C2-P3 iterates only the across cells inside the per-move, provably safe angle window `|θ| ≤ atan(rt / tipMin)` (tip at or below the pivot, a non-finite input, or a window covering the circumference falls back to the full loop); the window is solved once per move from the same `thetaAt` mapping, a seam-crossing window is two index ranges, and nothing outside it can lose material, so stored results are unchanged
- `playback.ts` — playback state: poses, options, grid cloning for stepped playback. Forward seeks advance incrementally (cuts are monotonic); the dirty region accumulates until the caller uploads and clears it; the transient square descriptor and immutable baseline ride along by reference while `topZ` and the `squareMaterial` interval map are copied, so a clone (and a `reset`) can never alias or drop the base grid's material

## Rendering (Three.js)
- `squareMaterialGeometry.ts` — actual square material boundary geometry (#1016 C2-R2M/R2MF): every interval clipped to the physical blank, true-pivot world coordinates, explicit axial bounds, triangular collapsed endcaps, shared angular partitions and incident radial corner knots for conforming adjoining faces; dirty regions reach touched angular chunks and neighbours/seam
- `squareMaterialMesh.ts` — owned chunked Three.js resource over the interval geometry: `createSquareMaterialMesh`, shared material, exact physical axial bounds, null unchanged/no-op updates, undefined full resets, dirty chunk replacement and idempotent disposal. The viewport's caller adapter is `components/simulation/squarePreview.ts` (physical ends from `getStockBounds`, shape/side-aware key, idempotent owned disposal)
- `gpuMesh.ts` — builds a `DataTexture` over the grid's `topZ` array and an instanced row-strip surface with one flat top per cell (no shared corners that can collapse narrow tab bridges); bounds cover the shader-displaced Y range; `uploadHeightfieldRegion` pushes only the dirty rectangle to the GPU via `texSubImage2D`
- `instancedBoundary.ts` — boundary walls + stock underside as instanced row-strips whose geometry the vertex shader derives from `gl_InstanceID` + the heightfield texture (GLSL3 `texelFetch`); O(cols) template memory at any detail, no CPU rebuilds while cutting. The heightfield boundary path for flat/round static and playback views. A step gets a wall lit by its own normal; a riser inside a slope is drawn too, but lit as the surface it belongs to
- `heightfieldShader.ts` — the heightfield surface shader material (`createHeightfieldMaterial`) plus the GLSL both meshes share: the `LIGHTING_GLSL` light rig, the `STEP_GLSL` step/slope predicate (`edgeIsStep`), and the smoothed surface normal (`SLOPE_GRADIENT_GLSL` + `SURFACE_NORMAL_GLSL`). The surface takes a lighting gradient only across an edge `edgeIsStep` calls a slope, interpolated across the cell so it is continuous over cell borders and widened when a cell is under a pixel; `instancedBoundary.ts` lights the steps it leaves flat, so the two meshes cannot disagree about which of them shades an edge
- `toolMesh.ts` — builds/disposes the moving cutter mesh group; a plasma torch gets the same plain flat-endmill cylinder as a flat endmill

- `squareMaterialMesh.test.ts` — resource layout, null geometry identity, interval-only dirty updates, neighbouring chunk content/seam dependency, reset, topology replacement, bounds, invalid inputs and exact idempotent disposal
- `aroundReplay.test.ts` — multi-turn folded replay, periodic cutter overlap on both seam sides and axes, dirty-region union, flat-reference parity and playback/scrub parity
- `aroundWrap.test.ts` — executes the actual scalar GLSL against the frozen rotary transforms on both axes in every quadrant; tests bar-group turn/tool placement, radial normals, cylinder bounds, the square corner envelope about the true pivot and compile-time material variants; also runs the seam's integer `aroundCell` lookup (both bar axes, along index never wrapped) and the `sameAroundFrame` comparison that keys the viewport's effects (issue #395 G3)
- `gpuMesh.test.ts` — heightfield texture/mesh construction and per-cell top geometry
- `tabbedEdgeSimulation.test.ts` — real rectangle/Edge Out/auto-tab toolpath replay at two detail levels, including playback and through-cut neighbors
- `instancedBoundary.test.ts` — strip template scaling, instance counts, group wiring, and the step predicate and surface normal the surface and walls share
- `heightfieldShader.test.ts` — the step/slope predicate and the lighting gradient's scalar helpers, run from the GLSL source: a ball scallop at ~3 cells per pass is a slope, tab bridges and cut-through rims stay steps, a step at or below half a cell is a slope, the gradient is continuous across cell borders and takes nothing from a step. The texture lookups and wiring around those helpers are restated in the test; the assembled shaders are covered by the rendered checks in `e2e/viewportViews.smoke.spec.ts`
- `glslScalar.testSupport.ts` — test support that compiles the shaders' scalar GLSL functions to JavaScript, so those tests call the text the GPU compiles rather than a TypeScript copy. `ivec2` is a plain `{ x, y }` and `int`/`ceil` are builtins, with function-read uniforms passed as `globals`, so integer code like `aroundCell` runs too (issue #395 G3)
- `replay.test.ts` — optimized cut-kernel parity against the `cutterSurfaceZ` reference; plus the wrapped round seam against the pre-change reference and the guarantee that flat/round grids gain no square keys
- `playback.test.ts` — playback move preparation, feed scaling, seek parity and dirty-region accumulation; plus the round clone key contract and wrapped round playback-versus-batch parity
- `squareGrid.test.ts` — square grid initialization: the true cross section seeded at every across cell, the immutable baseline, the corner render envelope with the pivot at side/2, virgin zero stats, old-grid key identity and descriptor validation
- `squareMaterialWindow.test.ts` — the per-move angle window (C2-P3): a seeded asymmetric move set (flat/ball, several radii, tips above/on/below the pivot, both senses, explicit and across-coordinate angles, seam-crossing windows, plunges, long and short moves) replayed window-versus-full-loop with bit-identical `topZ`, material intervals, `changedCount` and `dirtyRegion`; every cell outside the proven bound run through the full search on an isolated sheet and cutting nothing; and the tested-cell share on a `squareSimulation.test.ts`-style job
- `squareReplay.test.ts` — the physical square kernel against an independent machine-stock-space point-in-cutter oracle: the three measured C2-R1F defects (sloping-ball overcut, ball body floor, interior flat groove with its outer lip) are pinned to their independent references, the just-touch regression removes nothing, flat/ball cuts match to the oracle's radial resolution, an actual `generateRotaryRough` A0 pass leaves two surviving intervals with an oracle-agreed gap that later passes cannot resurrect, untouched ends keep their square section, seam/multi-turn identity, true pivot, above-envelope links remove nothing, clone isolation, and playback/seek/subdivision parity. C2-R1G adds the manager's narrow positive-contact rig (a sloping flat and ball window between scan nodes) across both axes, mm/inch, off-origin, translated, scaled and reversed, with whole-move versus 16/64/128-subdivision material intervals agreeing at a Float32 bound, plus its true-tangent counterpart (the same oblique geometry at zero clearance removes nothing); the manager's 16-case independent physical ball probe; the constant-angle-only supported regime (below-envelope angle-changing moves refused atomically, constant explicit `a` accepted, above-envelope turning links still zero-removal); interval-only stats/dirty tracking for an interior removal; and the actual generated rough/finish paths replayed batch-versus-playback with material intervals compared
