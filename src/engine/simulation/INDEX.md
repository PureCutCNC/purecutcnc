# INDEX — src/engine/simulation/

Material-removal simulation. Flat, round and square stock all use one radial
heightfield: `topZ` stores one height per cell and renders through a GPU
heightfield mesh. A square blank is the round bar's heightfield whose cells
start at the blank's true cross section; nothing downstream branches on stock
shape. Pure logic + Three.js mesh builders — no React.

## Core
- `aroundWrap.ts` — compile-time Around shader chunks: shared wrap and radial-normal formulas, periodic neighbor lookup and render bounds; `aroundBounds` is centred on the true pivot and defaults its maximum to the grid's radial envelope (`stockTopZ`), so a square blank's corners fit at `pivot ± side/√2` rather than a lifted `0..2·maxRadius` while a round bar stays byte-identical. The neighbour lookup is a preprocessor-free integer chunk (`AROUND_CELL_INDEX_GLSL`) so the scalar test support can run the GPU's own code; flat materials retain their original shaders
- `types.ts` — `SimulationGrid`, `DirtyRegion`, `SimulationBuildOptions`, `SimulationStats`; `stockTopZ` is the grid's enclosing radial maximum (the bar radius, or a square blank's corner radius) and `initialTopZ` is an optional immutable per-cell starting baseline used only by removal statistics. `SquareBarDescriptor` and `FlatRoundBarDescriptor` are initialization input; the grid carries no runtime stock-shape discriminator (the flat profile's `length` is what the static lower-half mesh spans)
- `grid.ts` — grid spec resolution and `createSimulationGrid` allocation. A square blank enters only here: `validateSquareBar` checks the descriptor, `seedSquareTopZ` fills each across cell with its starting radius (one native row fill per row on an X bar — identical floats, no per-cell write; issue #1112 rt2-e) `halfSide / max(|sin θ|, |cos θ|)` (constant along the bar), and `createSimulationGrid` snapshots the result as `initialTopZ`. `stockTopZ` is the corner envelope (`side/√2`); the true pivot stays `frame.radius`. A round bar on a flat Top/Bottom setup enters here too (issue #1049): `validateFlatRoundBar` checks its profile, `seedFlatRoundBarTopZ` fills each across cell with `pivot + sqrt(radius² − d²)` and starts cells with `|d| ≥ radius` at the grid's empty value, and the result is snapshotted as `initialTopZ`. It is a top-down heightfield, so only the bar's upper half exists; the descriptor is rejected together with `squareBar` or `wrap`
- `tools.ts` — `cutterSurfaceZ`: the cutter's lower-surface profile used to lower flat-grid cells; `cutterRayInterval` (and its allocation-free `cutterRayIntervalInPlace`) is the wrapped counterpart: the exact radial span the cutter's solid removes on one ray, solved in closed form for the flat cylinder, the ball nose plus shank, and the V-bit cone plus shank
- `replay.ts` — the one cutting path for every stock shape. `simulateOperationHeightfieldChunked` / `simulateReplayItemsHeightfieldChunked` are the same kernels driven in yielding slices with an `AbortSignal`, so the app can open the simulation panel before a heavy replay and cancel a superseded one (issue #1112 review P1). A flat grid and the plasma torch keep the flat-sheet kernel byte-for-byte (a torch cuts a flat one-kerf, full-depth slot along every torch-on move and a kerf-wide hole at each pierce). A wrapped (Around) grid dispatches to a second kernel that resolves each cell against the cutter's true solid (issue #1016 C2-F8): the unrolled across distance is arc length at the frame radius `R0 = period/2π`, so a cell at radius `r` and angle `D` sits `r·sin D` across the cutter and `r·cos D` along it, not flat. The cell keeps one radius, so only a cutter that reaches the outside lowers it; one that passes through the ray's middle leaves the outer shell. Its across bounding box uses the tight profile-specific reach (flat `R0·atan(rt/tip)`, ball `R0·asin(rt/(tip+rt))`, V-bit at its truncation) and cells at or below the move's deepest tip are skipped before the trig; every cell in the applied piece's footprint is resolved against all periodic images and their ray intervals are iterated to the order-independent fixed point (F8b), so overlapping seam copies cannot make finished playback differ from a batch replay and a cell the cutter already contains is removed in that frame; a move whose Z changes by more than one cell across the cutter's diameter is **swept** at one fixed set of absolute sample poses half a cell of Z apart plus each cell's nearest pose (`wrappedNeedsSweep`/`wrappedSweepSampleFractions`), because the disk edge reaches a cell before or after its closest approach and on an ascending move that earlier pose is lower (issue #1048 review); a playback piece applies exactly the samples with `t <= elapsed` (plus the nearest pose once the piece has reached it) and never adds the reached endpoint as an extra pose, so the union over any sequence of pieces is the batch and the finish equals it for every step size. Each cell evaluates only the sample poses whose cutter footprint can reach its current top — the along offset within `rt`, and the across reach `R0·asin(sqrt(rt² - along²)/top)` — widening the range as the fixed point lowers the top, so a circumferential ramp costs the cutter's footprint, not the move's sample count. The absolute sample schedule is cached per source move, grid cell size and cutter radius, so a move replayed once per frame derives it once and each piece only binary-searches the prefix it has reached (issue #1048 correction 3); a flat/drill cutter at a constant Z never evaluates the batch ceiling of a partial move, because every pose that reaches a ray removes to the same tip plane. A horizontal (or sub-cell-ramp) move keeps the exact nearest-pose path clamped to `min(t, elapsed)`, with the batch as a ceiling so a thread's next turn or a ring's far seam image cannot cut a slot the cutter has not reached. Statistics compare each cell with its own `initialTopZ` baseline when one exists (removed count, minimum top and maximum removed depth) and keep the uniform `stockTopZ` comparison for flat/round; the cell loop is allocation-free with per-move cutter dispatch (see `replay.test.ts` for the flat-sheet reference-parity contract). `setSweepScheduleObserver` is the opt-in diagnostic seam around that cache: it reports each real derivation (a cache miss) and nothing on a reuse — off by default, and it only reads the cache's decision, so enabling it leaves the grid byte-identical. It exists so the playback guard can count work instead of time (issue #1111)
- `edgeCrossings.ts` — where the cut really ends between cell centres (issue #973): the `grid.edgeCrossings` layout (4 bytes per cell: east and south crossing position and boundary angle; 0 = none), its encoders, plus its two writers: `outlineMasks` + `refineEdgeCrossings`, which `replay.ts`'s `CrossingFinalizer` runs after a static replay over the final outline cells only (tile-indexed, skipping tiles a move cannot reach the depth of), and `stampEdgeCrossings`, which the flat kernel calls during playback for cells near the rim of a move's reach (or where a ball or V-bit reaches the stock bottom). Both search only edges the shared step test could call a wall, places a through cut's edge where the tool leaves the stock bottom and a floor-to-floor step halfway up, replaces crossings when the move lowers the cell and keeps the further one when it only matches the depth. Crossing-only changes widen the move's dirty region. `replay.ts` exports `replayItemsIntoGrid`, the static replay both `simulate*Heightfield` functions run
- `playback.ts` — playback state: poses, options, grid cloning for stepped playback. Forward seeks advance incrementally (cuts are monotonic); the dirty region accumulates until the caller uploads and clears it; `cloneSimulationGrid` copies the mutable `topZ` and shares the immutable `initialTopZ` by reference, and `reset` restores the prior-operation base grid's heights. Each subdivided piece remembers the source move it came from and hands it to `applyMoveToGrid` as the `sweep` together with the fraction of it the piece has reached (`elapsedFractionOf`); the piece bounds only the elapsed footprint, so a partial application cuts what the cutter has actually reached (issue #1048) and the fixed point makes repeated pieces idempotent (issue #1016 C2-F8/F8b); a forward seek that lands within a rounding step of the end finishes the path, so `seekToFraction(1)` leaves `isFinished()` true. On a flat block (issue #1209) the clone copies `winners` and shares the move table; the controller gives the live grid the base table with its cutting pieces appended (`extendMoveTable`), passes each piece's own table index to the kernel, restores winners on `reset`, uploads any dirty region (a winner or crossing can change with no height changing), and reports `getWinnerProgress()` — the table entry being cut and its elapsed fraction — for the shader's clamp

## Rendering (Three.js)
- `gpuMesh.ts` — builds a `DataTexture` over the grid's `topZ` array and an instanced row-strip surface with one flat top per cell (no shared corners that can collapse narrow tab bridges); bounds cover the shader-displaced Y range through `aroundBounds` and the grid's radial envelope, so a square blank's corners are not clipped; `uploadHeightfieldRegion` pushes only the dirty rectangle to the GPU via `texSubImage2D`
- `instancedBoundary.ts` — boundary walls + stock underside as instanced row-strips whose geometry the vertex shader derives from `gl_InstanceID` + the heightfield texture (GLSL3 `texelFetch`); O(cols) template memory at any detail, no CPU rebuilds while cutting. The one heightfield boundary path for flat, round and square static and playback views, with the same radial-envelope bounds. A step gets a wall lit by its own normal; a riser inside a slope is drawn too, but lit as the surface it belongs to. `uWallFloorZ` is the lowest wall height — the stock bottom by default, the equator for a flat round bar's two along-end walls. A flat round bar (issue #1049) passes its descriptor instead: the group then carries no underside quad (its underside is the static lower half, not a flat stock bottom) and `ROUND_BAR_WALL_JOIN_GLSL` puts every side wall on the bar's cylinder — at the silhouette where the grid edge reaches the radius, a little below it where the cell boundary falls short, and pulled back onto the silhouette when an outermost cell boundary overshoots it — so the heightfield and the lower half meet on the bar's real circle at any grid spacing. Only that variant lights walls in world space and applies the lower half's depth darkening, so the join is one continuous shade; block, round and Around scenes build the same shaders and meshes as before. A square blank's bar view (`squareBlankSide`, issue #1112 rt3-b) is the one other variant: each wall's radius is clamped onto `SQUARE_BLANK_SILHOUETTE_GLSL`, because a square's section is widest at its cell centres and a wall could otherwise straddle the blank's true surface and leave a fin outside it under the uncut ends
- `flatRoundBarLowerHalf.ts` — the fixed lower half of a flat round bar (issue #1049): `createFlatRoundBarLowerHalf` builds a half-cylinder of the descriptor's `radius`/`length` about its pivot and centre, closed by half-disc end caps, from the same descriptor that seeds the grid. It shares the heightfield's colour, light rig and depth darkening, spans the lower semicircle only, and returns `null` for a block, square blank or Around setup, so every other scene is unchanged. Its equator ring is what the wall mesh's floor lands on; 1024 radial segments keep the polyline within 2e-4 units of the analytic circle at the joins the grid produces. Render-only: nothing cuts it, and it is created/disposed with the grid
- `heightfieldShader.ts` — the heightfield surface shader material (`createHeightfieldMaterial`) plus the GLSL both meshes share: the `LIGHTING_GLSL` light rig, the `STEP_GLSL` step/slope predicate (`edgeIsStep`), the smoothed surface normal (`SLOPE_GRADIENT_GLSL` + `SURFACE_NORMAL_GLSL`), `DEPTH_DARKEN_GLSL` (shared with the static lower half), `ROUND_BAR_SILHOUETTE_GLSL` (a flat round bar's material ends on its radius; the surface discards beyond it and the walls clamp onto it) and `SQUARE_BLANK_SILHOUETTE_GLSL` (`squareBlankSilhouetteRadius`: half the side on a flat, `side/√2` at a corner; the wrapped surface and its walls are clamped onto it so a square blank's bar view never draws outside the blank). The silhouette clamps are compile-time variants — a block, a flat setup and a round bar compile exactly the shader they had. The surface takes a lighting gradient only across an edge `edgeIsStep` calls a slope, interpolated across the cell so it is continuous over cell borders and widened when a cell is under a pixel; `instancedBoundary.ts` lights the steps it leaves flat, so the two meshes cannot disagree about which of them shades an edge. Walls along the cut outline (issue #973): `OUTLINE_WALL_GLSL` holds `wallFrom` (which edges leaving a corner are walls, by `edgeIsStep`) and `outlineCornerSolve`, the dual-contouring solve that places a corner on the boundary lines through its walls' edge crossings (within half a cell; a wall with no crossing stays on its cell edge) and gives the wall's direction there; `OUTLINE_CORNER_GLSL` reads a corner's offset from the precomputed texture and is the one reader the top surface, both wall strips and the underside (`OUTLINE_CELL_GLSL`) use, and `OUTLINE_NORMAL_GLSL` gives the wall strips their lighting direction from the same texel; all scalar-subset GLSL the tests run. `SHALLOW_SLOPE_CELLS` lives in `stepThreshold.ts` so the replay kernel shares it without importing three
- `moveTable.ts` — winner-move shading data (issue #1209): `SimulationMoveTable` (8 floats per move: from xyz, tool slot, to xyz, 0 — the GPU texel layout) with up to `MOVE_TABLE_MAX_TOOLS` tool slots, `WINNER_NONE`/`WINNER_UNKNOWN`, the append helpers the replay and playback use, `extendMoveTable` (playback's copy of the base table with its pieces appended), and `moveTableReach`, which the flat kernel's tie rule compares. A flat block grid carries `winners` (one `Uint32` per cell) and `moveTable` from `createSimulationGrid`; every other grid carries neither
- `winnerShader.ts` — the GLSL of winner-move shading: `WINNER_CUT_GLSL` (the kernel's per-move cutter height and slope, scalar so the tests run its own text) and `WINNER_SURFACE_GLSL` (the 2×2 winners plus each one's cut-order neighbours, read from the winner and move-table textures, with the playback clamp)
- `winnerShading.ts` — `createWinnerShading`: the R32UI winner texture (dirty-region uploads through `uploadTextureRegion`) and the RGBA32F move-table texture, the surface material's uniforms, `invalidate`/`update`/`setProgress`/`dispose`; null for a grid without winners or a table beyond WebGL2's guaranteed texture size
- `outlineCorners.ts` — the wall-outline corner texture (issue #973): `createOutlineCorners` owns one RGBA8 `(cols+1) × (rows+1)` render target filled by a GPU pass whenever the heightfield changes, and the grid's edge crossings as a `cols × rows` RGBA8 texture backed by `grid.edgeCrossings`. The pass runs `outlineCornerSolve` (`OUTLINE_WALL_GLSL`) once per corner and stores its X and Z offset (R, G) and the wall's direction (B, 255 = keep the face normal). `invalidate(region?)` marks the dirty cells' crossings for upload and their corners plus `OUTLINE_REACH_CELLS` stale; `update(renderer)` uploads the crossings (`uploadTextureRegion`) and reruns the pass scissored to them, and is called before every draw. Flat scenes only; a wrapped grid builds none
- `toolMesh.ts` — builds/disposes the moving cutter mesh group; a plasma torch gets the same plain flat-endmill cylinder as a flat endmill
- `simulationScene.ts` — `buildSimulationStockScene` builds and mounts one grid's complete renderable scene: the heightfield surface, the instanced boundary and (for a flat round bar) the static lower half, in one group, with the shared heightfield texture and, for a flat grid, the outline corner pass (`outline`) the caller invalidates on upload, updates before each draw and disposes. Both the static and playback viewport paths use it, so a view cannot mount a bar without the half below its equator; the caller owns and disposes the group and texture. `squareBlankSide` rides the same call and only reaches the wrapped square bar's two shaders

## Tests
- `aroundReplay.test.ts` — multi-turn folded replay, periodic cutter overlap on both seam sides and axes, dirty-region union, flat-reference parity and playback/scrub parity
- `aroundWrap.test.ts` — executes the actual scalar GLSL against the frozen rotary transforms on both axes in every quadrant; tests bar-group turn/tool placement, radial normals, cylinder bounds, the square corner envelope about the true pivot and compile-time material variants; also runs the seam's integer `aroundCell` lookup (both bar axes, along index never wrapped) and the `sameAroundFrame` comparison that keys the viewport's effects (issue #395 G3)
- `flatRoundBar.test.ts` — a round bar on a flat Top/Bottom setup (issue #1049): the seeded grid matches the analytic `pivot + sqrt(radius² − d²)` profile cell by cell on both bar axes, both units and both faces, cells outside `|d| ≥ radius` start empty, a block/square/Around grid keeps its exact output, a pocket lowers only cells the cutter reaches, and the descriptor is validated
- `flatRoundBarLowerHalf.test.ts` — the static lower half a flat round bar's scene must contain (issue #1049 follow-up): a half-cylinder of the bar's own radius and length, at or below the equator, on both axes, both units and both faces; a block or square scene builds none; the boundary wall floor joins the lower half (the silhouette at the radius, the cylinder where the grid stops short) and a block keeps the stock bottom; a flat round-bar scene has no stock-underside quad and its empty cells draw neither floor nor wall, run from `ROUND_BAR_WALL_JOIN_GLSL`; the heightfield's edge and the half-cylinder's equator ring coincide with matching outward normals; Ø40/Ø41 mm (and 1.52/1.55 in) at 96 cells put the outermost material boundary inside and beyond the radius and both still join the lower half with no gap or overlap past 2e-4; the shared scene builder mounts the lower half for the static and playback paths (removing either mount fails the source guard); and block and square boundary scenes hash byte-for-byte to their pre-change signatures
- `squareBlankBarScene.test.ts` — the square blank's bar display draws nothing outside the blank (issue #1112 rt3-b): the shader's own `squareBlankSilhouetteRadius` keeps every rendered radius inside the blank's cross-section and its two faces, on both bar axes and both units at the real seeded grid, while the unclamped cells provably overshoot it; the scene builder mounts exactly the surface and its boundary (no lower half, no extra mesh), wires the blank's side into the surface and both wall materials it mounts (dropping either forwarding call fails), and leaves every heightfield value untouched; and a block, a flat setup and a round bar compile the shader they had
- `winnerShading.test.ts` — winner-move shading (issue #1209): recording winners leaves every height byte-identical on a synthetic job of all profiles; the tie rule makes the winner independent of move order; playback (several step sizes, backward seek, reset) ends with a direct seek's winners and base table prefix; `WINNER_CUT_GLSL` run from its source equals the kernel's height at random points for every profile and its slope is the derivative; the 2×2 winners plus cut-order neighbours rebuild the exact height at 99.5 % or more of random points (and measurably fewer without the neighbours); a part-played move shows no cut ahead of the tool; and only a flat block with winners compiles the variant
- `outlineCorners.test.ts` — the outline wiring (issue #973): flat grids carry edge crossings and wrapped ones do not; playback's clone owns its crossings and a reset restores them; a pass that only moves a crossing still reports a dirty region; the tops, both wall strips and the underside bind the scene's one corner texture and read it through the shared reader rather than solving; only the wall strips read the direction; the pass compiles the shared step predicate and solve and reads the crossings; a wrapped grid builds no pass and compiles the cell-edge shaders; and random height and crossing changes move corners only inside the refreshed rectangle
- `gpuMesh.test.ts` — heightfield texture/mesh construction and per-cell top geometry
- `tabbedEdgeSimulation.test.ts` — real rectangle/Edge Out/auto-tab toolpath replay at two detail levels, including playback and through-cut neighbors
- `instancedBoundary.test.ts` — strip template scaling, instance counts, group wiring, and the step predicate and surface normal the surface and walls share
- `heightfieldShader.test.ts` — the step/slope predicate, the lighting gradient's scalar helpers and the issue #973 corner solve, run from the GLSL source against cuts stamped by the real kernel (a circular slot's wall corners within 0.02 cell of the tool's edge against 0.37 cell rms on cell edges, lit within 0.5° rms; straight slots at any angle within 0.02 cell; a ball cutting through ends where it leaves the stock bottom; crossing slots leave sharp corners; a stamped tab bridge narrower than a cell keeps its walls and real width (#829); two passes at one depth keep the outer edge; with no crossings nothing moves): a ball scallop at ~3 cells per pass is a slope, tab bridges and cut-through rims stay steps, a step at or below half a cell is a slope, the gradient is continuous across cell borders and takes nothing from a step. The texture lookups and wiring around those helpers are restated in the test; the assembled shaders are covered by the rendered checks in `e2e/viewportViews.smoke.spec.ts`
- `glslScalar.testSupport.ts` — test support that compiles the shaders' scalar GLSL functions to JavaScript, so those tests call the text the GPU compiles rather than a TypeScript copy. `ivec2` is a plain `{ x, y }` and `int`/`ceil` are builtins, with function-read uniforms passed as `globals`, so integer code like `aroundCell` runs too (issue #395 G3); it refuses `%`, which GLSL ES leaves undefined for a negative operand, so `aroundCell` wraps the seam with one add or subtract (issue #1154)
- `replay.test.ts` — optimized flat cut-kernel parity against the `cutterSurfaceZ` reference; the wrapped seam as a pure one-period translation (the old flat-sheet parity moved on purpose with F8) and the guarantee that flat/round grids gain no square keys
- `wrappedPlayback.test.ts` — a part-played wrapped move removes only what the cutter has reached (issue #1048): a hand-built three-turn thread with flat/ball/V-bit cutters, a Flutes-like twisted line, an around-the-bar ring, ascending and descending Z ramps (including the reviewer's 0.2-mm, k = 197 case and the 1.752-vs-2.109 ascending cell), plunges and a seam-crossing ramp are compared frame by frame with a batch replay of the path truncated at the playback fraction; every fraction check is symmetric (both directions within one cell) and asserts the playback itself removed cells, and the finish must equal the full batch for step sizes `totalPathLength/k`, `k ∈ {7, 53, 197, 1000}`, and for forward/backward seek sequences, not only a direct seek to 100 %. Frank's fixture at 2 % and 6 % uses the same symmetric check. Mutations: restoring the reached pose as an extra sample fails `steps/7`, and restoring the nearest-pose ceiling fails the ascending ramp at 10 %
- `playback.test.ts` — playback move preparation, feed scaling, seek parity and dirty-region accumulation; plus the round clone key contract and wrapped round playback-versus-batch parity
- `wrappedCutterGeometry.test.ts` — the wrapped cutter's true width (issues #1016 C2-F8/F8b): random moves on round and square grids, both bar axes and all three profiles, checked cell by cell against a dense physical oracle that tests points against the cutter's real solid (ramp moves are swept over the kernel's absolute sample poses plus the nearest pose, the #1048-review batch fix); a ray through the cutter's middle keeps the outer shell; the ball shank carries a ray the nose cannot; the 25 mm square-to-round case lowers zero retained-end cells; a round-bar groove matches the oracle through its walls; seam copies, playback batch == subdivided and reset; the reviewer's overlapping-seam move finishes playback exactly equal to batch under default, fine and unsplit pieces; a partial playback cuts the cell at (5, 0) at X = 4.5 while leaving a cell beyond the elapsed footprint alone; the 25 mm ball replay stays inside its CPU-time bound at detail 280 and 1120 on the program's constant-Z passes (the full flat reach mutation trips the 1120 bound), and the reviewer's circumferential ramp at detail 1120 stays inside a 50x ratio against the same XY move without a Z change, which never evaluates a sample (scanning every sample per cell trips it at 613x)
- `squareGrid.test.ts` — square grid initialization: the true cross section seeded at every across cell, the immutable baseline, the corner render envelope with the pivot at side/2, virgin zero stats, old-grid key identity and descriptor validation
- `squarePlayback.test.ts` — playback cost of the exact square-to-round job `e2e/rotaryModel.smoke.spec.ts` seeds (25 × 120 mm blank, 6 mm flat cutter, radial stock left on the rough): every viewport frame of the finish played from the prior rough, guarded by a **count of schedule derivations** (`setSweepScheduleObserver`) — at most one per source move / cell size / cutter radius, never one per frame (issue #1111) — plus a small explicit wrapped ramp replayed across many frames (non-empty schedule, one derivation), the cell-size and cutter-radius cache-key dimensions (including a cutter too small to sweep, which must derive an empty schedule), and a byte-identical grid with collection on versus off; the library-ball case keeps the CAM Add workload. The CPU-time ratio against the same moves and starting stock through the flat kernel (the reference never enters the wrapped path) is **opt-in**: `PURECUT_SQUARE_PLAYBACK_PERF=1 npx tsx src/engine/simulation/squarePlayback.test.ts`, because it tracked machine load and failed four builds during 0.6.0 (issue #1111); without the flag the default run prints one line saying it skipped the ratio and never calls `cpuRatio`, and with the flag the ratio and its raw times are printed and nothing about the ratio is asserted (five serial runs: baseline 4.89–5.09 against 4.94–5.55 with the per-frame rebuild restored, review P2 of issue #1111); a source-and-docs guard in the test fails if a threshold on the ratio returns to either. A per-frame schedule derivation still fails the counted guard; correction 3 passes (issue #1048)
- `squareReplay.test.ts` — the square blank through the shared kernel and playback: corner cells above the inscribed radius lower monotonically and never rise, a tool above the envelope removes nothing, angle-changing moves follow round behavior, a wrapped square grid uses the round seam copies, and batch/playback/subdivision/seek/reset agree. Statistics measure each cell's own baseline (a virgin square reports zero removed), and the actual generated rough keeps untouched ends square while the actual finish replays and seeks
